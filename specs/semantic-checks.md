# 确定性与语义检查边界

JSON Schema 用于解析 frontmatter 后的对象。必须启用 format checker 才能检查 UUID 和日期格式；部分实现把 format 当注释。模板中的双大括号占位符不是有效生产记录，实例化之后才做严格校验。YAML loader 若把日期解析为对象，应先规范化成 ISO 字符串。解析器还应拒绝重复 key，不能悄悄保留最后一个值。

确定性校验至少包括：

- 全库 id 唯一；重命名保留 id；新建分配新 UUID。
- sources 的本地链接必须存在，外部 URL 记录读取/捕获时间；网络不可达是待复核，不直接等同虚假。
- valid_from < valid_to，采用左闭右开区间；时间未知省略字段。日期精度不足时正文说明，不伪造精确时刻。
- updated_at ≥ created_at；recorded_at 是获取证据的记录时间，不等于有效时间。
- memory/decision 只有 explicit 或 observed 且 sources 非空才能 active；自动验证不能证明来源实际支持主张，需模型阅读或人工核查。
- supersedes/superseded_by 可解析且关系一致，不形成替代环；历史记录可查。
- source 正文更新必须作为新版本/有记录的纠正，不能用摘要覆盖。
- 对独立事实，冲突候选键为 subject/predicate/scope；还需基数与时间重叠判断。不宣称仅靠字符串匹配即可解决事实冲突。
- ~~operation ID 幂等；修改有 precondition hash~~（2026-11-24 裁决不采用）：写入前查目标文件 mtime，30 分钟内被其他会话写过则避让；同文件竞态用 git 历史恢复。
- 目标路径必须在授权根目录内，规范化后拒绝越界、路径穿越及指向根外的链接。
- 内容读取与写入均明确 UTF-8，写回时不丢失未修改正文。
- 同步、人工修改和其他 agent 不遵守 mtime 避让约定时，提示并保留冲突；文件改写不提供 CAS 或跨文件事务。
- 不建索引与派生向量视图（2026-11-24 裁决）；生成视图（Bases）直接读 Markdown 属性，不缓存副本。

AI 负责：识别相关性、来源是否支持、候选去重、冲突解释、知识综合。

程序负责：结构、路径、ID、时间格式、替代关系、来源存在性、明确基数约束。

人负责的重点是有歧义的价值判断和冲突；确定且已授权的小修改不应逐笔打断用户。
